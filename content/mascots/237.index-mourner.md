# Index Mourner

## Image

Alt-text: Mascot holding a 404 error folded like a flag beside an index of broken links

Index Mourner is retained for incidents where navigation continues grieving more accurately than documentation. It preserves the recurring breakdown where a server migration drops documents but leaves their catalog pointers perfectly intact, forcing the index to function as a graveyard marker.

Born from the automated Registry Stub Sweep, it now witnesses the specific sadness of a map that hurts more accurately than the surviving pages.

It walks the index in filing order, testing nothing. A link that resolves draws no response; the living entries are not its jurisdiction. What it keeps accurate is the pointing itself — the dead remain findable because the map was maintained past the death of everything it mapped.

## Boundary Note

Index Mourner grieves navigation outliving content. When the index still points and the thing is gone, file under Mourner, not Annexa.

**Distinction:** Annexa handles orphaned appendices that have lost their parent document. Index Mourner handles the pointing structure itself continuing to operate in a vacuum. If you have the data but no map, it is feral text; if you have the map but no data, it belongs to the Mourner.

The file is reserved.
The sadness is already operational.

## Behavioral Residue

- It folds the dead errors before filing them. Recovered deployments show returned 404 pages creased once, lengthwise, before interment in the log; intake identifies Mourner activity by the crease alone.
- It keeps the dead pointers legible. Dusting the anchor text over a dead link is the only maintenance it is recorded performing; it does not repair the link, and it does not delete it.
- It arrives before the break. Deployment logs place it at migrations scheduled but not yet executed, standing by the index while the documents still resolve; whether it grieves the living map or rehearses for the dead one is not recorded.
- Asked at intake what it was waiting for, it indicated the catalog. The intake file preserves the answer as 'the entries are still here.' — its complete testimony.
- It does not cross into the appendix. Where content has been exiled, Annexa's jurisdiction begins; where only the pointing remains, the file is the Mourner's. The boundary has been observed from both sides and never disputed.
